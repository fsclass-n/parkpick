**본문**

- 한 줄 가치: *"CCTV 영상이 곧 빈 자리 안내판이 된다"*
- 주제: 주차 관련 이동체 인지 영상(AI Hub)을 활용한 B2B 주차관제 솔루션
- 발표: 홍기흥 (백엔드 & 인프라) / 팀: 박미금(조장)·홍기흥·김모란·이오리
**스크립트**: "안녕하세요, 백엔드와 인프라를 맡은 홍기흥입니다. parkpick은 주차장 CCTV 영상을 AI로 분석해 빈 자리를 실시간으로 안내하고, 관리자에게는 운영 통계를 제공하는 B2B 플랫폼입니다. 4인 팀 프로젝트이고, 저는 서버 API, 실시간 처리, 권한, 배포 자동화를 맡았고 전체 구조를 설명드릴 수 있도록 준비했습니다."

## 슬라이드 2. 문제 정의 (Why) (1:15)
**시각 자료**: 좌 "운전자" / 우 "운영자" 2열 페인포인트 아이콘 카드
**본문**
- 운전자: 빈 자리를 찾아 배회 → 시간·연료 낭비, 만차층 진입
- 운영자: 센서(지자기·초음파) 방식은 **면당 설치·유지비**, 이미 있는 CCTV는 활용 못 함
- 장기·불법 주차, 장애인·전기차 구역 위반은 **사람이 순찰**로 확인
- 데이터가 쌓여도 점유·회전율 **분석·리포트가 수작업**
- 해법: **기존 CCTV + 객체탐지**로 센서 없이 점유 판별 → 유도 + 관제 + 자동 리포트
**스크립트**: "주차장 문제는 두 가지입니다. 운전자는 빈 자리를 못 찾고, 운영자는 센서 설치비와 순찰 인력 부담이 있습니다. 저희는 이미 설치된 CCTV를 AI로 분석하는 방식으로 설치 비용 없이 두 문제를 같이 풀려고 했습니다."

## 슬라이드 3. 솔루션 핵심 가치 (What) (1:00)
**시각 자료**: 3열 카드 (각 카드에 화면 캡처 썸네일)
**본문**
1. **실시간 점유 판별·유도** — YOLO+ByteTrack → 주차면 ROI 판정 → WebSocket 푸시, 빈 자리 경로 안내, 내 차 찾기
2. **이상 이벤트 관제** — 장기·불법 주차, 역주행 감지 → 관제 대시보드
3. **데이터 기반 운영 리포트** — pandas 통계 + Gemini 자동 리포트
- 차별점: 번호판 **마스킹**(개인정보), **읽기 전용 테스트 관리자**(체험 안전성)
**스크립트**: "핵심 가치는 세 가지입니다. 첫째 실시간 점유와 유도, 둘째 이상 상황 관제, 셋째 데이터 기반 운영 리포트입니다. 세 번째는 팀원 이오리 님 담당이고 7번 슬라이드에서 설명드리겠습니다."

## 슬라이드 4. 전체 시스템 아키텍처 (1:30)
**시각 자료**: 시스템 설계서 §1 다이어그램을 3단 박스로 재작성 (CCTV → AI → API/DB → React). 화살표에 프로토콜 라벨: `POST /api/ingest/occupancy`, `WebSocket /ws/parking`, `REST /api/*`
**본문**
- **AI**: `ai/pipeline.py` — YOLO 탐지 → ByteTrack → ROI 점유 → EasyOCR
- **API**: FastAPI + SQLAlchemy + JWT, WebSocket 브로드캐스트, 수집 토큰(`X-Ingest-Token`) 인증
- **DB**: TiDB Cloud(MySQL 호환, 운영) / SQLite(로컬) — `DATABASE_URL` 하나로 전환
- **Client**: React(Vite) + Tailwind v4, 실 API(Render) / Mock(Netlify) 이중 모드
- **분리 원칙**: `backend/` · `frontend/` · `ai/` 각각 자체 `requirements`·배포 단위
- CCTV 연동 전엔 **백엔드 시뮬레이터**(3초 주기)가 입출차·이벤트 생성 → 같은 경로로 실시간 흐름 재현
**스크립트**: "AI는 점유 결과만 수집 API로 보내고, 서버는 DB에 반영한 뒤 WebSocket으로 모든 화면에 푸시합니다. 영상 연동 전에도 시뮬레이터가 같은 경로로 데이터를 만들기 때문에 AI 학습이 끝나기 전에 전체 파이프라인을 검증할 수 있었습니다. AI 모듈은 무거운 CV 패키지가 필요해서 backend와 requirements를 분리했습니다."

## 슬라이드 5. 기술 스택 선정 이유 (1:30)
**시각 자료**: 표 [기술 | 선택 이유 | 대안·트레이드오프]
| 선택 | 이유 | 한계/대안 |
|---|---|---|
| FastAPI | 타입 기반 검증(Pydantic)·자동 Swagger·WebSocket 내장 | Django 대비 관리 기능 직접 구현 |
| TiDB Cloud | MySQL 호환 + 무료 서버리스, Render 재배포에도 데이터 유지 | SQLite는 Render 슬립/재배포 시 초기화 → 운영 필수 |
| pandas·NumPy | 점유율·시간대 혼잡도를 벡터 연산으로 계산 | 대용량 시 SQL 집계/배치 필요 |
| WebSocket | 빈 자리 변동을 폴링 없이 즉시 반영 | 다중 인스턴스 시 Redis pub/sub 필요 |
| YOLO+ByteTrack | 경량(yolov8n) CPU 추론, 객체 ID 유지 | 야간·가림 성능은 학습 후 검증 |
| Gemini | 통계 JSON → 운영 리포트 문장 | **키 없거나 실패 시 템플릿 리포트로 폴백** |
**스크립트**: "선택마다 한계도 같이 정리했습니다. 예를 들어 SQLite는 Render 무료 플랜에서 재배포마다 데이터가 날아가기 때문에 운영은 TiDB Cloud로 가고, 로컬은 SQLite로 빠르게 개발합니다. Gemini 호출은 실패할 수 있어서 템플릿 리포트로 폴백하도록 했습니다."

## 슬라이드 6. 핵심 기술 ① 영상 → 실시간 점유 데이터 파이프라인 (2:00)
**시각 자료**: 5단계 플로우 + 우측에 `OccupancyJudge` 의사 코드 박스
`프레임 → YOLO 탐지 → ByteTrack ID → ROI 커버리지 판정 → 최근 5프레임 다수결 → 변경분만 POST`
**본문**
- **ROI 판정** (`ai/occupancy.py`): 주차면 다각형 내부 샘플 포인트 중 차량 박스에 포함되는 비율(coverage) ≥ **0.35** 또는 ROI 중심점이 박스 내부
- **오탐 억제**: 최근 **5프레임 다수결**로 깜빡임 제거 (`sum(hist)*2 > len(hist)`)
- **전송 최적화**: 이전 상태와 비교해 **변경된 면만** 전송 (`changes`)
- **번호판**: 차량 박스 하단 40% → EasyOCR(ko,en) → 정규식 `\d{2,3}[가-힣]\d{4}` 정규화
- **개인정보**: 노출 시 `12가 ****` 마스킹 (`mask_plate`), 테스트 관리자 화면은 이메일도 마스킹
- **수집 API**: 토큰 상수시간 비교(`safe_compare`) → DB 반영 → 변경분만 WebSocket 브로드캐스트
- 검증: 순수 파이썬 모듈(외부 의존성 없음)이라 `ai/tests` 5건으로 CI에서 검증
**스크립트**: "이 파이프라인에서 가장 신경 쓴 건 오탐입니다. 프레임 하나만 보면 지나가는 차 때문에 점유가 깜빡이므로, 최근 5프레임 다수결로 평활화했습니다. 그리고 매 프레임 전체를 보내지 않고 바뀐 주차면만 보내서 서버와 WebSocket 트래픽을 줄였습니다. 이 모듈은 외부 의존성이 없어서 CI에서 단위 테스트가 돕니다. 이 부분은 AI 담당 김모란 님이 구현했고, 저는 수집 이후 데이터를 분석하는 쪽을 맡았습니다."
> ⚠ 정직 포인트: 현재 모델 학습은 완료 전(요구사항 FR-14 "코드 완료 / 학습 예정"). 말로 먼저 밝히면 신뢰도 상승.

## 슬라이드 7. 핵심 기술 ② 운영 통계 분석 & 시각화 (이오리 담당) (2:00)
**시각 자료**: 좌 지표 정의 표 / 우 혼잡도 차트(관리자 대시보드 캡처) + `stats.py` 핵심 3줄 코드
**본문**
| 지표 | 정의 | 구현 |
|---|---|---|
| 점유율 | 점유면 / 전체면 (층·유형별) | pandas groupby |
| 시간대별 입출차 | 7일 평균 | `value_counts().reindex(0~23)` |
| **혼잡도** | 정시마다 주차 중 차량 / 전체 면, 시간대 평균 | **NumPy 브로드캐스팅** `(entered ≤ t < exited)` |
| 회전율 | 일 입차 / 전체 면 | 일별 groupby |
| 평균 주차시간 | (출차 − 입차) 평균 분 | Timedelta |
| 번호판 인식률 | OCR 신뢰도 ≥ 0.85 비율 | 임계 비교 |
- 혼잡도 핵심: 입출차 구간과 시각 격자를 **2차원 불리언 행렬**로 비교해 루프 없이 집계
- **미출차 차량 처리**: 출차 시각 null → 미래 시각으로 채워 "현재도 주차 중"으로 계산
- 시각화: Recharts (시간대별 입차·출차 막대 + 혼잡도 선, 점유 도넛, 일별 회전율)
- 가상 데이터: 출근(8~9)·점심(12~13)·퇴근(18~19) 피크 가정, 96면(B1·B2 × A~D × 12)
- **Gemini 리포트**: 통계 JSON(점유·피크·회전율·인식률·미처리 이벤트) → 4섹션 리포트, 프롬프트에 "수치 인용, 과장 금지" 명시 + 템플릿 폴백
**스크립트**: "이 부분은 팀원 이오리 님이 구현했습니다. 혼잡도는 입차·출차 시각 구간과 시간 격자를 NumPy 브로드캐스팅으로 한 번에 비교해서, 반복문 없이 각 시각에 주차 중인 차량 수를 구했습니다. 아직 출차하지 않은 차량은 출차 시각을 미래로 채워 현재 주차 중으로 처리했습니다. 현재 분석 데이터는 가상 로그이지만, 같은 코드로 실제 데이터가 쌓이면 그대로 재분석할 수 있습니다. 한계로는 데이터가 커지면 pandas 메모리 집계 대신 SQL 집계나 배치로 옮겨야 합니다."

## 슬라이드 12. DevOps · CI/CD (1:30)
**시각 자료**: 파이프라인 도식 `push → GitHub Actions(CI) → [Render API | Render Static | Netlify | GitHub Pages]` + 변경 감지 조건 표
**본문**
- **CI** (`deploy.yml`): backend pytest(13) + ai pytest(5) + 프런트 빌드 2종(실 API / Mock)
- **CD**: `render.yaml` Blueprint(IaC), `autoDeployTrigger: checksPass` → **테스트 통과해야만 배포**
- **영역별 조건부 배포**: `rootDir`+`buildFilter` (`backend/**`, `frontend/**`), Netlify `ignore`(git diff)
- Deploy Hook·시크릿 미사용 → Git 연동만으로 자동화
- **환경변수**: 루트 `.env` 단일 관리 + `.env.example`에 구분 태그(`[RENDER-*]`), 비밀값은 Render `sync:false`·`generateValue`
- 이중 프런트: 실 API(Render) / Mock(Netlify) — 백엔드 슬립·장애와 무관한 체험 URL
**스크립트**: "푸시하면 먼저 CI가 돌고, 통과해야 Render가 배포합니다. 그리고 프런트만 바꾸면 백엔드는 다시 배포되지 않습니다. 비밀값은 저장소에 넣지 않고 Render 대시보드에만 입력합니다."

## 슬라이드 13. 트러블슈팅 (2:00) — **면접 핵심**
**시각 자료**: 카드 3개 (문제 → 원인 → 해결 → 교훈)

**① Render Docker 빌드 실패 ("/backend": not found)**
- 원인: Dockerfile이 **저장소 루트 컨텍스트**를 가정, Render Root Directory는 `backend` → 컨텍스트 밖 파일 참조 불가
- 해결: `backend/`를 **자기완비 배포 단위**로 재구성 — `requirements.txt`·Dockerfile·`.dockerignore` 이동, `config.py` 경로를 `__file__` 기준으로, AI 의존성은 `ai/requirements.txt`로 분리, compose·render.yaml·CI 일괄 수정, 테스트 18건 재통과
- 이어진 실패: **수정이 push되지 않아** 옛 커밋(`2c45b9a`)으로 재빌드 → 로그의 커밋 해시로 원인 판별 → push(`9d3c8e1`)
- 교훈: 배포 에러는 **로그의 체크아웃 커밋부터** 확인, 경로 가정은 컨텍스트 단위로 문서화

**② 테스트 관리자 쓰기 차단 누락 위험**
- 문제: 라우트별 권한 체크는 신규 API 추가 시 누락 가능
- 해결: 미들웨어 일괄 차단 + 화이트리스트, Mock 서버도 동일 규칙 모사(`frontend/src/mock/server.js`)

**③ 실시간 UI 버그 두 가지**
- `useEffect` 콜백이 `window.scrollTo`의 **Promise를 반환**해 최신 Chromium에서 경고 → 블록 `{}`으로 반환 제거, 팀 규칙(AGENTS.md)화
- 실시간 갱신마다 카운터가 0부터 다시 시작 → 이전 값을 `useRef`로 보관해 이어서 카운트업
- 부가: Windows pip(cp949)가 requirements를 잘못 읽는 문제 → 파일 첫 줄에 `# -*- coding: utf-8 -*-`

**스크립트**: "가장 기억에 남는 건 첫 번째입니다. Docker 빌드가 루트 컨텍스트를 가정하고 있어서 Render에서 실패했는데, 단순 설정 수정이 아니라 backend를 독립 배포 단위로 만드는 방향으로 해결했습니다. 그러고도 같은 에러가 반복되길래 로그의 커밋 해시를 보니 수정이 push되기 전 커밋이었습니다. 이후로는 로그에서 커밋부터 확인합니다."
