# parkpick 플랫폼 표준 아키텍처 및 UI/UX 가이드

## 1. 전역 레이아웃 및 헤더/푸터 공통화
- 모든 페이지(메인, 실시간 관제, 주차 유도, 내 차 찾기, 마이페이지, 관리자 등)에 같은 글로벌 헤더와 푸터를 공통 레이아웃 컴포넌트(`frontend/src/components/Layout.jsx`)로 고정 배치합니다.
- 처음 접속하면 항상 메인 페이지(`/`)로 진입하며, 서비스 소개·실시간 주차 현황 요약·주요 기능 진입 버튼을 보여줍니다.
- 로그인이 필요한 페이지(실시간 관제, 운영 리포트, 마이페이지, 관리자)는 비로그인 시 `/login?next=원래경로` 로 이동하고, 로그인 후 원래 페이지로 복귀합니다. (`ProtectedRoute.jsx`)
- 글로벌 헤더
  - 좌측: parkpick 로고 (메인 이동)
  - 중앙: GNB (실시간 관제 / 주차 유도 / 내 차 찾기 / 운영 리포트) + 관리자(관리자 권한일 때만)
  - 우측: 이상 이벤트 알림(WebSocket 실시간), 로그인/프로필 메뉴, 테스트 관리자 배지
  - 모바일: 햄버거 ↔ X 아이콘 전환, 우측 → 좌측 드로어 (body 포털 렌더링)
- 담당: 박미금(레이아웃·라우팅), 홍기흥(인증 가드 연동)

## 2. 주차관제 플랫폼 맞춤형 UI/UX 디자인
- 데이터 중심 대시보드: KPI 카드, 주차면 맵(SVG), CCTV 영상 분석 뷰(Canvas) 중심 구성
- 그리드: 12컬럼 반응형 (Desktop ≥1280px 컨테이너 / Tablet ≥768px / Mobile ≤767px)
- 여백: 8px 스페이싱 스케일 (8 / 16 / 24 / 32 / 48)
- 타이포그래피: 제목 `IBM Plex Sans KR` / 본문 `Noto Sans KR`, H1 32 · H2 24 · H3 20 · Body 16 · Caption 13 (`.pp-h1` ~ `.pp-caption`)
- 아이콘: FontAwesome 전 화면 일관 적용
- 주차 상태 컬러 시스템 (`index.css` `--color-st-*`, 맵·범례·차트 공통)

| 상태 | 컬러 | 토큰 |
|---|---|---|
| 빈 자리 | 그린 `#16a34a` | `st-empty` |
| 점유 | 레드 `#dc2626` | `st-occupied` |
| 장애인 전용 | 블루 `#2563eb` | `st-disabled` |
| 전기차 충전 | 시안 `#06b6d4` | `st-ev` |
| 예약/임시 | 옐로 `#eab308` | `st-reserved` |
| 이상 이벤트 | 오렌지 점멸 `#f97316` | `st-alert` + `animate-blink` |

- 관제 화면은 다크 테마 기본(토글 가능, localStorage 저장), 일반 페이지는 라이트 테마
- 담당: 박미금(디자인 시스템·화면), 이오리(통계 차트 데이터 규격)

## 3. 푸터 표준
- 서비스 정보(로고, 소개, 팀: 홍기흥(조장)·박미금·김모란·이오리), 고객센터(B2B 도입 문의, 운영 시간, 이메일), 정책(이용약관, 개인정보처리방침, 영상정보처리기기 운영·관리 방침), 외부 링크(GitHub, GitHub Pages, API 문서, SNS), 데이터 출처(AI Hub, 공공데이터포털), 저작권
- 우측 하단 원형 'To the Top' 플로팅 버튼: 320px 이상 스크롤 시 노출, 부드러운 스크롤로 최상단 이동
- 담당: 박미금

## 4. 권한 관리 및 인증 시스템

| 구분 | 진입 방식 | 권한 범위 |
|---|---|---|
| 일반 사용자 | 회원가입/로그인, 소셜 로그인(Google·Naver·Kakao), 일반 사용자 테스트 계정 | 실시간 현황, 주차 유도, 내 차 찾기, 리포트 조회, 마이페이지 |
| 실제 관리자 | `.env` 의 `ADMIN_SECRET_KEY` 로 관리자 키 로그인 (또는 `ADMIN_EMAIL/ADMIN_PASSWORD` 시드 계정, 관리자로 승격된 계정) | 전체 CRUD |
| 테스트 관리자 | 로그인 페이지 '테스트 관리자' 버튼 | 관리자 화면 전체 조회만 (Read-Only) |

### 실제 관리자
- 회원 권한 변경·삭제, 주차면 정보, CCTV 카메라·ROI, AI 모델 버전 적용, 이상 이벤트 처리, 운영 리포트 생성·삭제
- 보안 키 원본은 소스·프런트 번들에 포함하지 않으며 `.env.example` 에는 키 이름만 기재

### 테스트 관리자
- 프런트엔드: 헤더 'TEST ADMIN · 읽기 전용' 배지, 쓰기 버튼에 자물쇠 표시, 클릭 시 "테스트 관리자 계정은 읽기 전용입니다" 토스트 (`AuthContext.guardWrite`)
- 백엔드(최종 방어선): JWT `role: test_admin` 클레임 → `ReadOnlyGuardMiddleware` 가 `POST/PUT/PATCH/DELETE` 를 `403 {code: READ_ONLY}` 로 일괄 차단 (로그인/로그아웃 제외), 라우트별 `require_admin_write` 의존성으로 이중 차단
- 개인정보 보호: 번호판(`12가 ****`)·이메일 마스킹, 영상 분석 뷰의 번호판·얼굴 블러

### 공통 보안 규칙
- 모든 권한 검증은 백엔드에서 최종 수행, 프런트 분기는 UI 표시용
- 관리자 주요 작업은 `audit_logs` 테이블에 감사 로그로 기록
- 담당: 홍기흥(인증·권한 API, 미들웨어), 박미금(권한별 UI 분기), 김모란(영상·번호판 마스킹)
